# 知账后台管理端

## 定位与入口

管理端随 NestJS 后端一起构建和运行，不需要独立前端服务：

- 页面：`/admin`
- API：`/admin-api/*`
- 本地入口：`http://127.0.0.1:3006/admin`
- 生产入口：`https://zhizhang.kagurayami.top/admin`

管理端不加入宣传站导航、站点地图或公开页面文案，并设置 `X-Robots-Tag: noindex, nofollow, noarchive`。

前端静态文件位于 `backend/admin-ui/`，NestJS 模块位于 `backend/src/admin/`。镜像构建时将静态文件复制到运行镜像，数据接口由 `AdminController` 提供。

## 功能范围

- Dashboard：用户、账单、版本、Issue、注册趋势和收支汇总。
- 系统配置：功能开关、更新策略和支持信息。
- 版本管理：版本号、下载地址、更新日志和强制更新策略。
- 用户管理：分页、搜索、状态筛选、新增、编辑、停用、重置密码和删除。
- Issue 管理：缺陷、功能、优化和维护事项，支持状态、优先级、目标版本、负责人和标签。

## 认证边界

管理端不复用普通用户 JWT。真实值只放在被 Git 忽略的 `backend/.env.admin`，模板见 `backend/.env.admin.example`：

```env
ADMIN_USERNAME=管理员账号
ADMIN_PASSWORD=高强度随机密码
ADMIN_JWT_SECRET=独立的高强度随机 JWT 密钥
ADMIN_API_KEY=高强度随机发布密钥
```

网页登录成功后获得由 `ADMIN_JWT_SECRET` 签名、有效期 12 小时且带 `scope=admin` 的管理员 JWT。自动发布使用请求头 `x-admin-key`，不保存管理员密码。

以下版本写接口受管理员保护：

- `POST /app-version/upload`
- `DELETE /app-version/:id`
- `/admin-api/*` 全部管理接口

客户端读取版本的 `GET /app-version`、`GET /app-version/latest` 和 `GET /app-version/check` 保持公开。

## 数据模型

管理端使用 Prisma 的 `SystemSetting`/`system_settings` 和 `AdminIssue`/`admin_issues`。Compose 启动时会通过 `prisma db push` 同步 schema，必须继续使用外部业务卷 `zhizhang-postgres-data`，不能创建空卷替代现有数据。

## 本地启动

```powershell
cd D:\Dev\Projects\Zhizhang\backend
Copy-Item .env.admin.example .env.admin
# 编辑 .env.admin，替换全部占位值
docker compose up -d --build app
```

## Android 发布关系

`mobile/scripts/release.js` 从被忽略的 `mobile/.env.production` 读取 `ADMIN_API_KEY`，上传 APK 时发送 `x-admin-key`。该值必须和后端 `backend/.env.admin` 一致，脚本不得打印密钥。

## 生产运维

生产项目目录为 `/opt/zhizhang`，Compose 服务名为 `backend`，容器名为 `zhizhang-backend`。常用命令和数据保护规则统一见 [部署与运维](部署与运维.md)。

生产配置文件应保持最小权限；管理员认证异常时依次检查 `.env.admin` 是否挂载、`ADMIN_JWT_SECRET` 是否稳定、数据库 schema 是否同步，以及反向代理是否仍指向主生产 API。
