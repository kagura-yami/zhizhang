# 知账宣传网站部署与服务链路

## 当前生产链路（已上线）

```text
用户浏览器
  │ HTTPS
  ▼
note.kagurayami.top
  │ 阿里云 ECS OpenResty：TLS、域名入口
  │ 当前站点请求统一转发到 FRP 远端端口 7017
  ▼
47.110.32.161:7017（frps）
  ▼
本机 remote-frpc：7017 → host.docker.internal:3006
  ▼
Docker zhizhang-backend:3006
  ├─ Express 静态宣传站：backend/public/site/
  ├─ /app-version*：NestJS 版本接口
  ├─ /downloads/*：backend/public/downloads/（APK、热更新包）
  ├─ /uploads/*：backend/uploads/（运行时头像）
  ├─ /api-docs：Swagger
  └─ 其他业务 API：NestJS Controller
```

宣传网站已部署到本机 Docker 映射目录 `backend/public/site/`，该目录和根目录 `website/` 均被 Git 忽略。后端启动时通过 `express.static` 提供网站文件；这不会覆盖 `/app-version`、`/downloads`、`/api-docs` 或业务 API 路由。

前端动效采用静态站可直接承载的组合：CSS View Transition 做页面切换，Motion for JavaScript（`animate`、`inView`、`scroll`）负责视口入场、滚动联动和微交互，IntersectionObserver 做无依赖降级 reveal，GSAP + ScrollTrigger（CDN 可用时增强）做体验页/能力页滚动入场，Canvas 粒子层提供轻量环境动效。技术方向参考 Moonshot 首页的“客户端路由 + WebGL 氛围层 + 叙事滚动”思路，但不复制其资源或品牌。

桌面端滚轮监听会将一次有效滚轮手势映射到下一个 `.snap-section`，使用 RAF quintic ease-in-out 自定义过渡，并在动画期间暂停原生 snap 与 CSS smooth scroll；滚动按慢→快→慢连续推进，长内容章节在抵达边缘前保留自然滚动，避免跳过体验步骤。移动端保留触控惯性并通过 CSS `scroll-snap` 对齐。导航采用固定的无边框渐变导航层，滚入第二屏后仍保持可用；窄屏启用折叠菜单。

## 日常发布宣传网站

```powershell
cd D:\Dev\Projects\Zhizhang
Get-ChildItem website -File | Where-Object { $_.Extension -in '.html','.css','.js' } | Copy-Item -Destination backend/public/site -Force
Get-ChildItem website/assets | Copy-Item -Destination backend/public/site/assets -Recurse -Force
docker compose -f backend/docker-compose.yml restart app
```

如果修改了 `backend/src/main.ts`，使用完整重建：

```powershell
docker compose -f backend/docker-compose.yml up -d --build app
```

不要执行 `docker compose down -v`，以免误删外部 PostgreSQL 业务卷。

## 将来切换子域名

推荐把宣传站迁移到独立子域名，例如 `promo.kagurayami.top`：

1. 在 DNS 添加新子域名 A/AAAA 记录，指向同一 ECS。
2. 在 ECS OpenResty 新增独立 `server`，根目录指向 ECS 上的静态发布目录（例如 `/opt/zhizhang-website/current`）。
3. 将 `/app-version*`、`/downloads/*`、`/api-docs` 和需要的业务 API 反向代理到 `http://127.0.0.1:7017`；或继续使用当前 FRP 端口映射。
4. 申请并配置新域名证书，检查 `server_name`、HTTP→HTTPS 重定向和安全组 80/443。
5. 验证新域名页面、版本 JSON、APK 下载和 OAuth 回调后，再将旧域名根路径从后端入口切换为兼容重定向。

网站代码中的下载和版本接口使用相对路径，迁移域名不需要改 API 代码。分享卡片中的 `og:url` / `og:image` 若要完全匹配新域名，再批量替换 HTML 元信息即可。
