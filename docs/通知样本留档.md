# 自动记账通知样本

本功能用于保存支付相关通知原文及对应规则的提取结果，供排查误识别和建立回归测试。客户端实现版本为 `0.0.136`（Android `157`），发布前必须先部署新增后端接口和表。

## 采集与上传

- 自动记账开启且用户已登录时，采集已配置监听应用中的支付相关通知。微信要求支付官方通知身份；银行短信要求银行来源；不采集普通聊天、验证码、动态密码。
- 原文字段包括标题、大标题、正文、展开正文、文本行、副标题、摘要、ticker、频道和通知 key；同时记录通知发布时间、捕获时间、应用版本、规则版本。
- 状态分为 `queued`（进入记账队列，**不表示入账成功**）、`deduplicated`（被记账队列去重）、`ignored`（未满足解析条件）和 `error`（处理异常）。识别成功时附完整提取结果。
- 应用私有 SQLite `notification_samples.db` 先存待上传样本，网络恢复后重试，每批最多 25 条。样本绑定捕获时用户，切换账号不会传到另一账号；未登录时不采集。
- 相同用户、通知 key、发布时间、原文字段和规则版本生成稳定指纹；同一通知反复扫描不重复留档，正文变更保留新样本。
- 云端确认后移除本地原文，只保留 30 天已上传指纹；未上传原文不按时间自动删除。云端目前保留至账号删除，不设自动过期任务。
- 历史版本没有留档的原文无法从账单摘要恢复。上线前的截图只能作为合成测试依据，不能冒充真实通知样本。

## 后台使用

生产入口 `/admin` → **通知样本**，支持用户 ID、来源包名、规则版本、处理状态筛选。详情显示原始通知字段、提取结果和时间信息；JSON 导出保留当前筛选条件，按 ID 游标取完全部批次。

接口：

- `POST /notification-samples/batch`：普通用户 JWT，所属用户从认证上下文取得，不接受客户端指定用户。
- `GET /admin-api/notification-samples`：管理员认证，分页查看。
- `GET /admin-api/notification-samples/export`：管理员认证，每批最多 1000 条，通过 `nextAfterId` 继续获取。

## 部署

新增 Prisma 模型 `NotificationSample` 和表 `public.notification_samples`。增量 SQL 位于 `backend/prisma/migrations/202609160001_notification_samples/migration.sql`，只新增表、索引与用户外键。既有生产环境通过 `db push` 管理结构，应先核对迁移历史，再选择运行该增量 SQL 或兼容的迁移命令；不得直接对现有业务库重置迁移或允许数据丢失。

先部署后端、生成 Prisma Client 并检查管理员查询和用户上传，再发布 APK。后端未就绪时客户端会保留待上传记录，但不能把排队当成云端留档成功。

当前提取改进：交易金额避开同分句的余额、原价、优惠；渠道模板不冒充交易对象；微信转账、零钱充值、退款给出简短摘要；普通充值不自动归为居住；满减营销红包不作为入账。
