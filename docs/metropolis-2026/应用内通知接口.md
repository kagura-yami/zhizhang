# 应用内通知与已读边界

2026-09-16，本批仅完成通知读取和已读后端。R07 仍需移动端首页票数/圆点、通知列表、其他事件来源、合并和系统投递。

## 接口和客户端调用顺序

- `GET /social/inbox?after=0&limit=20`：当前用户的事件流，按事件 ID 向前读取，最多 50 条候选。响应包含 `items`、`nextAfter`、`hasMore` 和 `receipt`。隐藏或失去权限的事件不返回，但游标仍前进；即使 `items` 为空也要按 `hasMore` 决定是否继续。它不是全站未读总数接口。刷新时从 0 重新读取，以获得历史项的最新权限和已读状态。
- `POST /social/inbox/read`，请求 `{ receipt }`：确认当前用户已读。列表凭证只包含实际返回的事件 ID；重试幂等，不影响未展示的事件。
- `GET /social/inbox/threads/:id`：在与文字发送相同的用户锁下捕获线程当前最高事件 ID，返回该边界及有效未读条数和凭证。

进入评账详情时必须**先获取线程边界，再读取并展示详情，显示成功后再确认凭证**。不能先读详情、再捕获边界，否则两次请求之间新到的消息可能被错误确认。列表返回本页凭证，只有页面真正展示后才确认。凭证 15 分钟过期，绑定用户和用途，不可作为登录令牌。并发到达且位于边界之后的反馈始终保留未读。

## 权限与预览

目前接入已存在的主评、回复、申请状态和举报结果事件。投票/改票没有事件，不产生文字未读。修改、撤回、恢复也不新增提醒。

通知读取重新查询原线程、原文字和授权。评价者失去授权或账单不再可见时不返回该通知；主人仍可读取自己的存档。撤回或审核隐藏的文字不出现在通知内容或未读文字计数里。私密线程不会向第三位用户开放。申请只展示当前有效版本，拉黑后不再返回相关申请通知。

默认正文预览为空，不返回金额或账单备注。用户开启预览后，只返回仍可读文字的当前版本，最多 120 字符。审核说明不进入锁屏预览。`systemNotificationEnabled` 表示后续系统投递是否启用；关闭系统提醒不删除应用内历史，也不自动标记已读。当前接口没有实际发送系统通知，后续投递时仍须重新授权检查。
