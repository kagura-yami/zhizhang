# 评账申请（本地实现，待生产发布）

新增申请状态机，遵循完整需求中的申请限额和冷却规则，不将其从正式范围删除。

## 接口

普通用户 JWT；成功 `{ success: true, data }`。owner 为账单主人，applicant 为申请查看账单的人，不会同时建立关注。

| 方法/路径 | 参数/行为 |
|---|---|
| GET `/social/requests/incoming` | 本人收到的申请，分页 |
| GET `/social/requests/outgoing` | 本人发出的申请，分页 |
| GET `/social/requests/to/:ownerId` | 当前账号对此人的申请、全站待处理数、上限与冷却截止时间；校验双方可见性 |
| POST `/social/requests/to/:ownerId` | 首次 `{}`；重新申请需 `expectedVersion` 为上次结束版本 |
| POST `/social/requests/to/:ownerId/withdraw` | `{ expectedVersion }`，仅本人可撤回 |
| POST `/social/requests/from/:applicantId/approve` | `{ expectedVersion, scope, historyStart? }`，仅主人可批准并设范围 |
| POST `/social/requests/from/:applicantId/reject` | `{ expectedVersion }`，仅主人可拒绝 |

状态：pending / approved / rejected / withdrawn / system_cancelled。版本在重开及每次结束时递增，旧界面不能处理新一轮。重复相同结束操作返回原结果，不重复计数或通知。重复待处理申请返回原记录，不占第二个名额。

## 并发与规则

- 所有创建、撤回、处理均先锁双方用户行；申请人行串行化跨主人的全站限额。最多十条 pending，一对账号最多一条。
- 拒绝后可重新申请；连续第三次拒绝启动 24 小时冷却，同时将申请人的其他 pending 全部标记 system_cancelled，不算额外拒绝。
- 任一申请批准清零连续拒绝次数；撤回不增不减。冷却过期不会复活已取消申请，需要重新提交；新冷却周期开始时清零上一周期计数。
- 拉黑取消双方未处理申请，后续批准被阻止；解除拉黑不恢复申请和权限。
- 主人直接授予权限时，同一对账号的 pending 申请一起转 approved，防止“已获授权但仍待处理”；过期批准界面不会覆盖新的授权。
- 申请人/主人、收支/历史范围都由服务端验证，批准不自动关注或反向授权。

## 通知状态

创建申请通知主人，批准/拒绝通知申请人的事件已与业务状态一起写入 `social_inbox_events`，有唯一去重键。事件读取与已读凭证接口已完成，**尚未完成应用内消息 UI 或系统推送投递**，不能声称用户已经收到通知。系统取消不是拒绝通知。

## 手机端 0.0.138 / Android 159

设置 → 社群与隐私 → 评账申请，提供收到/发出分页名单。关系页展示申请状态、全站待处理名额和冷却截止时间，可发起、重新申请或撤回。收到的申请可以拒绝，或进入原四字段授权确认页选择范围后批准。批准不自动关注，不自动双向授权；已批准记录不会被展示成当前授权有效的证明。
