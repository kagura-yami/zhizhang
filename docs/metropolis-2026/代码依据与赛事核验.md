# Project Context Analysis

## Analysis Purpose

把参考方案中的私密评账、排行榜和 AI 消费复盘融入现有知账，准备杭州路演及 Metropolis 新增工作说明。本轮只做方案与材料，不修改业务实现、不发布新版本。

## Codebase Structure

| 实际文件 | 核查结果 | 本轮意义 |
|---|---|---|
| `backend/prisma/schema.prisma` | 有 User、Bill、Budget、ChatSession、ChatMessage、NotificationSample；没有社交授权、评账或链上凭证模型 | 新增领域模型，继续引用现有用户和账单 |
| `backend/src/bills/bills.service.ts` | 账单金额 Decimal；统计按 income/expense 求和；删除为物理删除；退款有 relatedBillId | 不能直接把现有统计称为净消费；评账存档不能随账单删除 |
| `backend/src/budgets/budgets.service.ts` | 月/年预算按当前周期查询；没有历史预算版本 | 历史复盘不能假装知道当期预算 |
| `backend/src/ai/tools/tool-definitions.ts` | create_bills、query_bills、delete_bills、get_statistics | 已有工具调用基础，不等于已有复盘 Agent |
| `backend/src/ai/services/tool-executor.service.ts` | 创建工具返回候选账单，交前端确认；查询上限 50 条 | 复盘必须新增完整聚合入口，不能用默认 20/最多 50 条查询冒充全量 |
| `backend/src/ai/services/chat.service.ts` | 已有模型适配、会话保存、工具调用循环，上限 5 轮 | 复用适配层，另建受限的只读复盘编排 |
| `mobile/src/navigation/AppNavigator.tsx` | 首页、统计、中间记账、AI 助手、我的 | 先从“我的”进入社群，不挤入第六个底部 Tab |
| `mobile/android/app/src/main/java/com/zhizhang/notification/PaymentNotificationParser.kt` | 支付通知规则提取；本地已补券提醒过滤、金额和摘要规则 | 输入质量是复盘前提，不是链上真实性证明 |
| `backend/src/notification-samples/`、`backend/admin-ui/` | 本地已实现原文批量上传、管理员查看和导出 | 原文仅用于规则迭代，不进入社群响应或链上 |

## Dependencies

现有：React Native 0.81.4 / React 19、React Navigation、React Query；NestJS 10、Prisma 6、PostgreSQL；OpenAI 兼容模型与其他适配器。根目录编排 backend/mobile，非共享工作区包。

尚缺：社交消息服务、可靠通知投递、复盘作业与结构化报告、钱包签名和链适配器、合约与独立校验器。本次检查未在 backend/mobile 包依赖中发现 ethers/viem 或可直接复用的完整远程社交通知通路；现有 Android 支付通知监听不能当作服务端推送服务。

## Connections

现有链路：Android 通知 → 原生解析与去重 → 账单 API → Prisma → 报表/AI 工具。AI 对话经用户认证，工具执行收到服务端 userId。

拟新增链路：Bill → 统一统计口径 → 授权最小字段投影 → 私密评账 → 复盘输入快照 → 只读模型编排 → 用户私有报告。可选导出链路另见方案；不能把 NotificationSample 原文串入社交链路。

## Architecture Patterns

保持 NestJS 领域模块化单体、Controller/DTO/Service 分层，复用 PrismaModule 和 JWT 用户认证。管理员继续使用 AdminAccessGuard。移动端按 Screen → Hook/React Query → API service 增加功能。

## Codebase Conventions

新增模型遵循现有数据库映射和用户归属字段；金额使用 Decimal 或明确的定点字符串；时间段在服务端统一；DTO 校验和服务端授权一起执行。环境凭据不进入演示材料。生产数据库迁移采用可演练的增量变更，不能清空卷或对生产执行破坏性重置。

## Key Insights

1. Bill 只有 income/expense，没有币种字段和规范的内部转账分类。人民币演示可以成立，多币种与真实财富排名不能成立。
2. 退款关联存在，但当前分类支出求和不会自动扣掉退款。排行榜和复盘必须共享新增口径。
3. 预算无历史版本。针对旧月只能展示“预算资料缺失”或“以当前预算作参考”，不能写“当月超支”。
4. Bill 物理删除与“保留社群存档”冲突，必须新增最小快照并调整删除事务。
5. 原文留档和 0.0.136 / Android 157 属于本地已实现待发布工作；此前生产已验证的发布为 0.0.135 / Android 156。本轮没有再次逐项验收生产功能，不把本地实现标作生产可用。
6. 本轮社群、复盘、凭证均为提案，没有合约地址、交易哈希或实测新功能可演示。
