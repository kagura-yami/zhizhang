# 统一口径预算进度

新增 `GET /budgets/ledger-progress`，用户 JWT 必填，从认证身份获取本人有效预算，返回 `{ success: true, data: [...] }`。不接受其他用户 ID、历史日期或预算快照参数。本批仅后端，手机预算页及首页预算卡片尚未切换；旧 `/budgets/progress` 暂保留兼容，不能据此声称全应用预算口径已统一。

## 计算规则

按 UTC+8 请求时刻选择当前完整自然月/年，账单 DATE 不经过服务器本地时区。预算设置和范围内全部账单在同一个 RepeatableRead 事务中读取，五百条一页。同周期、同分类的多个预算共享累加结果，避免重复扫账单。

使用额取共享 LedgerAccumulator 的 `grossExpense`，只包含已确认的普通消费；内部转账、调账、忽略项排除，未知、过期确认、非人民币等依原规则标记待确认。退款单列为 `refundInflow`，不从使用额扣除。分类范围按当前账单的 categoryId 匹配，退款字段也按其自身分类统计，不根据原消费关联重新分摊。总预算取全范围；分类预算只对本分类中的待确认记录标不完整。

该接口比较的是**当前预算设置**：`configurationBasis=current`、`spendingBasis=gross_expense`，不是过去某天真实存在的预算。历史复盘仍使用 BudgetHistoryService，不能拿这个接口回填过去预算。

## 返回字段

每项含预算 `id/name/period/categoryId/category/amount/alertAt/updatedAt`，以及：

| 字段 | 含义 |
|---|---|
| ledger | 本范围完整账务汇总、起止日期、规则版本、排除与待确认数量 |
| spent / refundInflow / remaining | 四位小数字符串；remaining 可以为负，不把超额归零 |
| progressPercent | Decimal 计算、四位小数字符串，不截断超过 100% 的真实比例；零预算或无效金额返回 null |
| comparisonStatus | complete / incomplete / invalid_budget |
| confirmedOverBudget | 已确认消费是否已经超过额度；这是已知部分的判断 |
| isOverBudget | 只有预算金额有效且账务完整时才给出布尔值；不完整或无效时为 null |
| needsAlert | 已确认消费是否达到提醒阈值；不能将 false 当作完整的“预算安全”结论 |

零预算且存在已确认消费时，确认部分超支且需要提醒，进度比例为 null；不得显示除零值或“正常使用 0%”。金额无效时比较结果不成立。停用预算不返回；分类删除由既有数据库触发器停用关联预算，不能悄悄变成总预算。

## 验证与部署

`backend/test/budget-progress.integration.cjs` 使用本机合成数据库验证 JWT、用户隔离、506 条跨页覆盖、四位精度、退款分离、重复范围预算、分类边界、不完整/过期确认、零预算、UTC+8 年月切换及分类删除。已接入 `npm run test:social:integration`，该命令仍从旧 schema 执行正式迁移后测试。

本接口没有新增迁移，依赖已规划的分类表及预算历史迁移，特别是分类删除停用触发器。后端编译、专项测试、十一组升级数据库组合回归及四适配器模拟测试通过，临时容器自动清理。移动端保持 0.0.146 / Android 167；生产 SSH 尚不可用，未发布生产、未更新线上版本记录。
