# 私密评账（后端实现，未生产发布）

本批新增投票、主评、私密回复、文字版本，以及账单修改/删除的历史处理。用户端页面、未读游标、举报审核入口和 AI 引用尚未完成，不能据此宣称整套社群已可投入使用。

## API

普通用户 JWT；成功响应 `{ success: true, data }`。金额四位小数字符串。所有 threadId/messageId 查询均在服务端校验参与者及当前授权，不能用猜测 ID 跨用户读取。

| 接口 | 行为 |
|---|---|
| PUT `/reviews/bills/:id/vote` | `{ vote: "hang" | "la" }`；一人一账单一票，可改不可取消；返回本人 threadId 和 vote，无他人统计 |
| GET `/reviews/bills/:id/summary` | 仅主人查看票数与评价者列表，分页；删除账单后保留存档统计 |
| GET `/reviews/mine` | 本人收到的评账线程和最小快照，分页 |
| GET `/reviews/threads/:id` | 本线程消息、最新基础字段、删除/修改标记，消息分页 |
| POST `/reviews/threads/:id/main` | `{ clientKey: UUID, body }`；仅评价者，先投票、一条主评 |
| POST `/reviews/threads/:id/replies` | 同上；仅主人与该评价者私密双向回复 |
| PATCH `/reviews/threads/:id/messages/:messageId` | `{ expectedRevision, action: "edit" | "withdraw" | "restore", body? }`；只能改本人文字 |
| GET `/reviews/threads/:id/messages/:messageId/versions` | 本线程双方按当前权限查看文字版本；违规隐藏时拒绝访问 |

文字最长 2,000 字符，不接受空白；按纯文字处理。clientKey 用于创建幂等，同一键不同内容冲突。版本过期返回 409，不覆盖别人刚更新的文本。无主评不能发回复；没有投票就没有可写主评的线程。

## 可见性和状态

- 评价者仅看自己的票和线程，不能取得其他人的文字、历史或总票数。主人可分别看全部属于本人账单的线程。
- 主评自行撤回显示占位，线程暂停回复；恢复沿用原记录和旧对话。编辑、撤回、恢复保存版本但不产生新文字通知事件。
- 违规隐藏正文和历史均不返回普通用户；隐藏主评不阻断其余回复。此批通过测试数据库设置 hidden 验证规则，正式后台审核入口仍待实现。
- 每次读写都复查授权、拉黑、收支与历史范围；授权结束后评价者失去历史读取权，主人仍可只读查看，双方不能继续互动。
- 首次主评/回复持久化唯一通知事件，不将原文写进通知 payload；投票和改票不产生通知。实际消息 UI、未读和系统推送待后续实现。

## 账单生命周期

`BillsService.update/remove` 与社交读写共享有序用户行锁。修改账单更新最小快照并显示修改标记，保留投票；范围变动立即影响评价者访问权。

删除时在同一事务中保存金额、收支、分类和时间快照，设置删除标记并清空 billId，再删除原账单。对话不会随 Bill 外键删除，只有主人可以读取存档；账单本身无可查的版本历史。
