# 统一账务口径接口（开发完成，待部署）

本模块为排行榜与 AI 复盘的共享基础，尚未替换旧版首页统计，也尚未接入移动端确认页面。不能将本模块通过测试视为社群或复盘已经完成。

## 接口

用户 JWT 必填。服务端从 JWT 取用户，不接受调用方指定账本 ownerId。

- `PUT /ledger/bills/:id/classification`：请求 `{ kind, currency: "CNY", expectedUpdatedAt }`。kind 为 ordinary / refund / internal_transfer / adjustment / ignored。expectedUpdatedAt 使用获取账单时原样返回的 updatedAt，必须包含时区；账单变动返回 409，跨用户访问返回 404。
- `GET /ledger/summary?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`：最多 366 天。金额以四位小数字符串返回。cashSurplus = ordinaryIncome + refundInflow − grossExpense；同期间退款、其他期间退款、未关联退款分别返回。

确认仅影响共享新口径，不修改原始金额。未知/过期确认不参与新统计，`complete=false`、`counts.needsReview` 和最多 50 个 pendingBillIds 告知数据缺口。实际聚合不截断；账单查询每 500 条并在同一 RepeatableRead 快照中计算。内部转账、调账和 ignored 分开计数，不被当作消费。

只支持人民币。未完成的确认 UI 和批量核对交互是后续必须交付的内容；不自动把全部旧账单认定为 ordinary。

## 迁移与兼容

增量迁移：`backend/prisma/migrations/202609160002_ledger_classification/migration.sql`。仅增加确认表及外键，不改写历史账单，不修改旧 Bill 响应。账单删除时确认表级联删除；未来社群历史存档是另一个对象，不能依赖此表。

部署前备份、核对生产迁移基线，先建表再发布新后端。回滚优先退回原后端并保留新增确认表，不需要删数据。
