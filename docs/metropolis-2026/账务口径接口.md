## 接口

用户 JWT 必填。服务端从 JWT 取用户，不接受调用方指定账本 ownerId。

- `PUT /ledger/bills/:id/classification`：请求 `{ kind, currency: "CNY", expectedUpdatedAt }`。kind 为 ordinary / refund / internal_transfer / adjustment / ignored。expectedUpdatedAt 使用获取账单时原样返回的 updatedAt，必须包含时区；账单变动返回 409，跨用户访问返回 404。
- `GET /ledger/summary?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`：最多 366 天。金额以四位小数字符串返回。cashSurplus = ordinaryIncome + refundInflow − grossExpense；同期间退款、其他期间退款、未关联退款分别返回。
- `GET /ledger/analytics?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`：相同日期和身份约束，返回 `summary`、`daily`、`monthly`、`categories`。各组沿用完整的 LedgerAccumulator 数字与数据缺口字段，日/月按自然日期顺序并补齐空周期；分类按 ID 分组，无分类为 null，不通过同名合并。
- `GET /ledger/bills/:id`：本人账单的确认上下文，包含 `updatedAt`、现有分类、`needsReview` 和 `canBeRefund`。跨用户返回 404，不返回关联他人账单的内容。
- `GET /ledger/pending?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&afterId=0`：仅本人待确认账单，每页 20 条，返回 `nextAfterId/hasMore`。使用 ID 游标覆盖全部待确认项，不受 summary 的 50 个提示 ID 上限限制。

确认仅影响共享新口径，不修改原始金额。未知/过期确认不参与新统计，`complete=false`、`counts.needsReview` 和最多 50 个 pendingBillIds 告知数据缺口。实际聚合不截断；账单查询每 500 条并在同一 RepeatableRead 快照中计算。内部转账、调账和 ignored 分开计数，不被当作消费。

只支持人民币。确认页要求用户选择真实交易口径并重新勾选人民币/真实性确认；原账单修改后旧确认返回 409。重新加载后的确认状态与新上下文绑定，不能沿用旧勾选。批量核对交互及旧统计/预算口径整合仍需后续完成；不自动把全部旧账单认定为 ordinary。

## 日/月趋势和分类统计

`analytics` 在一次 RepeatableRead 事务中完整读取每页五百条，同一笔数据同时进入总额、对应自然日、自然月和分类聚合。金额始终用 Decimal 计算并返回四位小数字符串，不返回账单备注、通知原文或描述。内部转账、调账、忽略和待确认各自计数，不混入普通收入或消费。前端必须展示不完整状态，不能把待确认金额当成零消费结论。

日分组的退款来源期间是该自然日；月分组是查询范围与该月的交集；总额及分类使用整个查询范围。因此同一笔退款可能属于“月内退款”但属于“其他日退款”，这是分组口径差异，不能把日分组的同期间退款简单相加当作整月同期间退款。净结余和普通收支则可以按日或月加总。查询不经过服务器本地时区。

本批仅增加统计后端接口，旧 `/bills/statistics`、首页月汇总和预算进度仍保留原实现，移动端保持 0.0.145 / Android 166。前端切换、预算整合及相应视觉/原生验证仍未完成，不能宣称页面口径已统一。

真实数据库测试覆盖 506 条账单跨页覆盖、总额与 summary 一致、日/月空周期、分类及无分类、不完整和过期确认、退款来源日/月差异、跨年/部分月边界、身份隔离、无原文泄露和非法日期范围拒绝。后端编译及十组升级数据库组合回归、四适配器本地模拟测试通过，测试容器已清理。
