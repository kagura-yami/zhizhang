# 社群权限基础（后端已实现，未生产发布）

本批覆盖显式启用、隐私偏好、用户检索、关注/互关、名单权限、拉黑、单向评账授权和最小账单投影。不代表移动端社群已经可用；申请、评价、通知、排行及 AI 仍须后续交付。

## 接口约定

全部使用普通用户 JWT；成功响应 `{ success: true, data }`。分页 `page` 从 1 开始，默认 pageSize=20，最高 50。UUID 入口校验并统一小写，避免大小写绕过自操作限制或有序锁。

| 接口 | 用途 |
|---|---|
| GET `/social/me` | 是否启用、本人设置及当前同意版本 |
| POST `/social/enable` | `consentVersion: "2026-09-16"` 加可选偏好，显式启用；幂等保留首次启用时间 |
| PATCH `/social/preferences` | AI 文字使用同意、关系公开、排行范围/金额、通知开关和预览偏好 |
| GET `/social/users?query=...` | 昵称模糊/完整 UUID 精确检索；排除未启用与拉黑双方 |
| GET `/social/users/:id` | 最小资料和本人对该用户的关注/互关状态 |
| GET `/social/users/:id/relations/:kind` | following/followers/friends，别人名单需主人公开 |
| PUT/DELETE `/social/following/:id` | 关注/取消；关注不授予账单权限 |
| GET、PUT/DELETE `/social/blocks[/:id]` | 本人拉黑管理；拉黑结束双向关注与授权，解除不恢复 |
| GET `/social/grants/:direction` | given/received 的本人授权关系（含已结束状态） |
| PUT `/social/grants/given/:id` | 创建/修改本人授予对方的权限 |
| DELETE `/social/grants/given/:id` | 主人撤销 |
| DELETE `/social/grants/received/:id` | 评价者退出 |
| GET `/social/owners/:id/bills` | 按有效授权读取四项业务字段，无其他私有字段 |

创建授权参数 `{ scope: "expense" | "income" | "both", historyStart?: "YYYY-MM-DD" | null }`；修改已有授权必须提交 `expectedVersion`，冲突返回 409。历史日期必须真实存在。不存在/结束授权或拉黑返回 403。主人主动创建授权立即生效，遵循参考方案单向授权约定；退出后若要阻止再次授权可使用拉黑，独立拒收邀请设置尚未实现。

启用默认不参榜、不公开准确金额、不公开关系名单、不把评论送 AI、不展示系统通知正文。此批只保存排行/通知设置；相关下游功能尚未实现，不能称为通知已送达或排名已公开。

## 权限与数据边界

普通用户公开资料仅 id、nickname、avatar，不包含登录名、邮箱、密码、最后登录等字段。授权账单仅 id（操作定位）、amount（四位小数字符串）、type、category（名称）、date 和 time，不返回 Bill 的完整对象。

“仅新账单”同时要求 createdAt 不早于 activatedAt，且业务日期不早于授权激活时的北京时间日期。允许历史时按指定业务日期下限查询。修改有效授权不重置首次激活时刻；结束后重开使用新的激活时间。

关系写入和受保护读操作按 UUID 顺序取得双方用户行锁，避免关注/授权与拉黑并发重建权限。每次读取重新执行中央授权检查；修改授权用版本条件防止覆盖。后续评价写入也必须通过相同服务，不能只在 UI 隐藏。
