# AI 复盘作业与历史

本增量完成后端持久化作业、本人报告历史及失效处理；手机端入口、真实模型质量评测和生产部署仍未完成。移动端保持 0.0.144 / Android 165。

## 接口

全部沿用 JWT 登录身份，不能传入其他 ownerId，返回 `success/data`。

| 方法与路径 | 用途 |
|---|---|
| POST `/ai/retrospectives` | 创建：`clientKey` UUID、`kind` day/month、已结束 `period`、可选本人的 `configId` |
| GET `/ai/retrospectives?page=1&pageSize=20` | 本人历史元数据分页，不返回报告文字或内部来源映射 |
| GET `/ai/retrospectives/:id` | 本人报告及 `sourceChanged`；有效结果含版本、模型、生成时间、摘要和实际引用的跳转 ID |
| POST `/ai/retrospectives/:id/retry` | 重试失败任务；最多总计三次尝试 |
| DELETE `/ai/retrospectives/:id` | 删除正文与来源，取消本进程在途请求；保留不含原文的幂等墓碑 |

同一用户和 clientKey 只创建一次任务；换周期复用同一 key 返回冲突。未指定配置时在入队时固定本人的默认配置 ID。每用户最多一个 queued/running 任务，滚动二十四小时最多新建二十个任务。删除后重放旧请求只返回 deleted 状态，不重新生成；用户主动再次生成必须使用新 key。

## 后台执行

`RetrospectiveJobsService` 随 Nest 后端启动，每三秒领取一次，单进程不重叠执行；数据库条件更新保证多进程竞争只有一个获得同一任务。十分钟租约配合随机 token，旧执行者无法覆盖新状态。

进程中断后，租约过期转 failed/interrupted，等待用户重试，不自动反复调用付费模型。正常上游请求超过一百二十秒会取消；关闭应用会取消本进程在途请求。`RETROSPECTIVE_WORKER_DISABLED=1` 仅用于测试或维护暂停队列，仍可查询历史。后台数据库异常只记限频通用日志，不输出原文或上游错误正文。

状态为 queued、running、succeeded、failed、invalidated、deleted。invalidated 不允许重试覆盖原报告，需新建复盘。失败状态仅保存受控错误码。

## 原报告与隐私撤回

报告保存生成时的结论、模型和规则版本，不随普通账单或评价编辑静默改写。详情重新取当前证据，摘要不同时显示 `sourceChanged`，同时保留旧报告。原文引用的内部作者 ID、授权时间等不返回客户端；只提供报告实际引用的账单/文字/投票跳转 ID。

在发送给模型前，作业先登记全部参与生成的来源，再重新检查证据摘要。数据库触发器将以下变化与报告失效放在同一事务内：评价隐藏、撤回；作者撤销 AI 授权；主人撤销使用收到反馈；社群退出；作者账户停用。失效会清除报告正文、撤销运行租约；恢复文字、重新授权或重新激活不会复活旧报告。

读取时还有防御性核验，检查用户有效、作者授权、原文字是否仍存在且可见。删除源文字的异常路径也不能通过旧报告读出。列表不返回正文，不能绕过详情校验。用户删除报告后，旧工作进程不能重新写回；用户删除账号则级联删除其作业。

原始请求已经发往模型之后的授权撤回不能“收回”远端收到的内容，但报告不会再被接受或展示。任何未来报告导出都必须复用详情权限与失效检查，不能直接导出数据库 result。
