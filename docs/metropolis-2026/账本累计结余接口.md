# 账本累计结余与近十二月趋势

`GET /ledger/cash-history`，认证用户只读取本人账单，不接受其他用户 ID 或自定义历史范围。

## 含义与范围

这是按当前账单及当前确认状态重建的累计现金结余，不是银行账户余额、真实净资产，也不是当时保存的月末快照。没有期初资产、负债或全部资金账户数据时，不能把它命名为“净资产”。原资产页的 `收入 - 支出` 与前端浮点反推逻辑应在移动端接入时替换。

服务端以 UTC+8 当前月份为截止，读取截至本月最后一天的全部历史账单；超过本月的未来账单不计入。近十二月为本月及前十一月，含空月份。本月已记录的未来日期包含在内，与首页、统计和预算自然月范围一致。

普通收入 + 退款 − 消费 = 已确认部分累计结余；内部转账、调账和忽略项排除。未知、过期确认和非人民币账单等沿用 LedgerAccumulator 的待核对规则。没有猜测旧记录，也没有把未确认记成零金额。

## 返回数据

响应为 `{ success: true, data }`：

| 字段 | 内容 |
|---|---|
| basis / classificationBasis | `reconstructed_cash_surplus` / `current`，明确重建依据 |
| summary | 截至本月末全部历史的已确认金额、完整性、计数和日期范围 |
| opening | 近十二月开始之前的全部账务汇总；无历史记录时为零且完整 |
| window | 近十二月完整账务汇总 |
| monthly | 正好十二个月的当月事实，以及累计值 `cumulativeCashSurplus`、累计待核对数量 `cumulativeNeedsReview` 和完整标记 `cumulativeComplete` |
| categories | 近十二月按分类 ID 分组的完整收支/退款事实，空分类独立保留 |

金额均为 Decimal 四位小数字符串。累计趋势以 opening 的已确认结余为起点逐月累加，最后一个月累计值等于 summary 的结余。历史待核对数量会传递至每一个后续累计点：某月没有新增待核对账单，不代表该月累计历史完整。

summary、opening、月份和分类均在同一 RepeatableRead 事务内读取，每页 500 条，读取全部符合范围的记录，无总条数截断，不返回通知原文或备注。事务超时返回失败，不返回部分累计结果。本接口没有新增迁移。

已加入后端组合回归执行器，从旧 schema 执行正式迁移后验证。手机资产页尚未接入；当前移动端仍为 0.0.148 / Android 169。生产尚未发布，不能将接口完成当作资产页或真实净资产功能已完成。
