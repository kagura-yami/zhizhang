# AI 复盘取数与证据

当前取数服务已随 0.0.152 生产后端上线，复盘入口位于可选社群。本文描述取数边界；真实模型质量与真机验收仍未完成。原有分批实现状态以《生产交付进度》更新为准。

## 完整取数

只接受已结束的 UTC+8 自然日或自然月，用户身份由调用方从认证上下文传入。账单、分类汇总、有效文字、投票和预算均在同一个 PostgreSQL RepeatableRead 快照内读取。账单和文字按 500 条游标翻页直到结束，不使用聊天工具的 50 条上限，不静默截断输入；事务超时则整个取数失败。

金额复用 `LedgerAccumulator` 的四位小数口径。所有当期账单均保留在事实输入中，包括无人评价、数据异常和明确排除的条目，并逐条标记是否计入汇总；总额和分类总额均由服务器计算。不会读取发票、邮箱、账户凭据或审核后台保存的历史原文。

模型载荷使用 B/M/V 局部引用及“本人/评价者 N”别名，不发送用户 UUID、昵称或头像。另行保留内部来源 ID、账单内容指纹和文字修订版本，供后续报告引用校验、来源变化检测和隐藏处理使用；这些内部来源映射不得作为模型输入。输入摘要不包含每次变化的抓取时间，相同证据得到相同摘要。

## 双向授权

- `allowAiFeedback`：本人允许复盘使用收到的评价。
- 新增 `allowAiAuthoredFeedback`：本人允许自己的投票及文字用于账单主人的 AI 复盘，默认 false，独立于第一项。旧版设置不会自动开启它。
- 文字必须作者账户有效、作者独立授权、未撤回、未违规隐藏。本人回复也需要本人作者授权；它在结构中标为 owner，不得当成好友意见。
- 无获准的好友文字时，明确提供数据缺口，不编造“朋友认为”。投票与文字分开提供，不能把投票推断成具体文字理由。
- 当前主人按既有权限规则保留撤销授权后的线程阅读权；删除账单的存档不进入当期有效账单复盘。每次取数重新检查当前授权，不使用旧采集缓存。

新字段已接受布尔偏好更新，拒绝 null；手机端已提供独立说明与开关。报告生命周期已实现生成及读取时的权限和来源校验；详见《AI复盘作业与历史》。

## 预算

日复盘按月初/年初至当天结束计算累计支出；月复盘按当月/年初至该月结束计算。稳定预算才产生比较，历史不足和期间变更明确标记。比较基准为 `gross_expense`（毛支出），退款流入单列，不把跨期退款直接解释成当期消费减少。存在非法金额或不支持币种等数据异常时，超预算结论为 null。期间变更计数是相应查询窗口内所有预算规则变更的保守提示，不等于当期稳定预算数。

## 验证

`backend/test/retrospective-evidence.integration.cjs` 仅接受本机 15448 端口的 `zhizhang_evidence_test` 数据库。真实 PostgreSQL 16 验证 501 笔账单、503 条有效文字、分类汇总、精确金额、跨用户隔离、作者授权撤销、隐藏/撤回、删除账单、UTC+8 结束边界、当期预算，以及旧偏好升级不自动授权。Prisma 迁移后 schema diff 无差异，后端 37 项单元测试及编译通过。

临时测试容器用完移除。生产已应用迁移 `202609160012_ai_author_consent`。本专项现纳入组合回归，在全量迁移及生产触发器下执行；无人工分类的正常账单仍计入金额。
