## 交付约定

- 每个可验收更新批次：实现 → 测试 → Git 提交 → 发布 → 线上验证。移动端变更必须递增版本与 Android versionCode，构建 Release 并同步版本接口。
- 未能发布的批次明确记为待发布，不用本地通过代替生产通过。不为通过发布门槛省略需求。
- 保留原有未提交且不属于本批的工作，不把删除文件或配置变化混入功能提交。
- 支付行为需要确定具体场景；已询问 AA 结算 / 有限授权自动支付 / 稍后决定。可独立推进社群与复盘，但不把 Track 04 的报告 hash 当成 Track 02 支付功能。
