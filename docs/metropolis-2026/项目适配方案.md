# 知账：私密评账与有据复盘方案

版本：讨论稿 V1 · 2026-09-16。产品方向建议，不是已批准的全量开发合同。

## 1. 产品定位

**知账帮助用户自动记录消费，在自己选择的关系中获得反馈，并把账单事实、朋友意见转化为可执行的 AI 复盘。**

首批目标用户：愿意记账、但看完统计仍不知道怎么调整的年轻职场人，以及已经有信任关系的朋友或伴侣。优先验证二至五人的小圈子，避免一开始建设陌生人公共信息流。

用户价值分三层：减少记录成本；让消费得到有上下文的讨论；每次复盘只给少量、可以执行并在下次检查的建议。社群不以羞辱、炫富或投资推荐获得互动。

产品主线：自动记账 → 主人修正可疑条目 → 主动授权 → 好友私密评账 → AI 日/月复盘 → 下次查看行动进展。链上凭证是可选的输出能力，不是记账前提。

## 2. 对参考方案的取舍

| 参考项 | 建议 | 原因 |
|---|---|---|
| 在现有 App 新增社群而非重做产品 | 保留 | 账单、AI、预算、登录可复用 |
| 单向授权，关注不等于看账权 | 保留 | 权限边界清晰 |
| 评价者之间不可见；仅主人看全量反馈 | 保留 | 符合私人财务场景 |
| “夯/拉”投票＋文字＋主人回复 | 保留；辅以“值得/可再想想”解释 | 保留辨识度，避免外部评委不理解 |
| 首页只显示票数和新文字反馈圆点 | 保留 | 不破坏现有首页 |
| 所有关注名单公开 | 改为默认不公开，后续可主动开启 | 财务关系本身可能敏感 |
| 启用默认全站榜、准确金额公开 | 改为默认不参榜，加入时默认好友范围且隐藏金额 | 不把财务曝光作为使用社群的代价 |
| 全站日/月/年排行榜首版齐全 | 后置，先好友月榜 | 当前口径与封榜基础不足；不作为路演关键路径 |
| 任意用户主动申请＋三次拒绝全站冷却 | 后置；首轮主人主动授权，接收者可拒收/退出 | 先验证真实邀请，避免复杂申请系统和骚扰 |
| 退出后可随时被再次立即授权 | 调整为退出者可拒绝该人的再次邀请 | 尊重接收者选择；邀请接受前不推送账单 |
| 全部功能第一版上线 | 改为闭环试点后逐项开放 | 9 月 19 日路演与正式全量上线是不同目标 |
| 历史文字全部可回看，撤回可恢复 | 保留数据模型能力，试点先编辑/撤回；恢复后置 | 必須处理违规隔离和删除，不只做 UI |
| 用户主动生成结束日/月复盘 | 保留 | 输入边界确定，避免实时误导 |
| 评论可送 AI，仅入群一次说明 | 改为单独告知并记录同意；未同意的作者文字不送第三方模型 | 公开社群和向模型服务披露不是同一件事 |
| 不储值、不托管、不转移资金 | 保留 | 与现有产品、参考方案边界一致 |

上表均为本方案建议；未回复的产品偏好不能视为已确认。社群试点建议免费；平台承担模型成本时设置透明额度与失败重试规则，不承诺无限免费模型调用。

## 3. 首版体验与最小闭环

### 入口

底部继续使用首页／统计／记账／AI 助手／我的。“我的”新增“社群评账”，进入后包含互评账单、我的反馈、关系管理；排行榜准备好再开放第四项。账单详情新增查看评价；AI 助手内新增“昨日复盘”“选择已结束月份”和历史报告。

### 演示故事

小林授权小周、小陈查看今天之后的支出基础信息。午餐 ¥32 和一笔娱乐消费 ¥168 入账，两人分别给评价。小林能看到两个私密线程，小周看不到小陈的观点。次日复盘将消费事实、预算依据、朋友建议分开，形成“下次先检查已有订阅”等行动。上述姓名、金额均为演示样本，不用生产用户数据。

### 授权

授权主体固定为 owner → reviewer；仅支出为默认；字段固定为收支类型、金额、分类、发生时间和当前账单是否修改。服务端构造专用 DTO，禁止包含 description、counterparty、notes、账户、原通知、发票和邮箱信息。自定义分类名称也可能含敏感信息，授权确认页必须展示实际字段示例，允许主人先改分类名。

默认仅新账单：同时满足 `createdAt >= grant.activatedAt` 且业务日期不早于授权生效的北京时间日期。补录过去账单不因此绕过历史授权。开放历史时使用主人选择的最早业务日期；修改旧账单不改变 createdAt、不重新通知。扩大或缩小权限后立刻重算可见范围。

授权可撤销；接收者可拒收/退出并阻止再次邀请；任何一方拉黑则双向终止关注、授权与待处理邀请。每次查询/写入/深链/导出/通知投递都重新检查。授权终止后主人保留自己的存档，评价者无历史读取权。

### 评账与文字

每账单每评价者最多一票，取夯或拉，可改票。一个私密主线程，发主评前必须投票。主人不自评；主人可回复。票数只对主人聚合展示；评价者只得到自己的票与线程。编辑留版本，撤回显示占位且暂停该线程回复，违规隐藏不开放原文历史。

社群不是实时聊天。首版先做应用内未读和刷新；远程系统推送后续接独立投递服务，不宣称复用 Android 支付通知监听即可完成。未读用服务端事件序号/游标，进入详情只推进到请求时最高序号，不吞掉并发新消息。投票不提醒，文字才提醒；通知默认不含金额或正文。

### 举报与删除

试点对外开放前具备举报入口、管理员隐藏、审核日志、拉黑和限流。后台只看被举报线程的必要上下文。被隐藏内容不得通过版本接口、AI 引文或导出重新暴露。

现有 Bill 物理删除必须改为事务：先把四项最小基础字段写入 ReviewSubject 存档，关联 billId 置空，标记已删除，随后删除账单；私密线程保留给主人。避免以 Cascade 删除全部证据。账号删除时按业务删除策略清理个人社交数据；违规证据隔离保存且有明确保存期，不能无限留存所有原文。具体保存期在正式开放前形成可执行政策，方案不假定现有合规结论。

## 4. 财务口径先于排行榜与 AI

新增共享 `LedgerSemanticsService`，不复制现有 sum 逻辑。建议 Bill 增量增加 `entryKind`（ordinary/refund/internal_transfer/adjustment/unknown）、`classificationStatus`（confirmed/needs_review）与币种；历史数据不凭关键词批量断言转账性质。首轮仅人民币，不跨币种加总，不把 CNY 与测试币放进同一榜。

| 条目 | 期间结余 | 消费分析 | 处理 |
|---|---|---|---|
| 工资/真实收款 | 收入 | 非消费 | 普通条目 |
| 普通消费 | 减少 | 计入支出 | 普通条目 |
| 已关联退款 | 收到退款日计入流入一次 | 同期展示毛支出、退款流入；跨期退款单列 | 不在现金结余中二次抵扣 |
| 自有账户间充值/转账 | 不计收入或支出 | 不计消费 | 仅已确认 internal_transfer 可排除 |
| 给他人转账 | 按真实业务性质 | 可为支出 | 不能看到“转账”就排除 |
| 优惠券、满减提醒 | 不生成有效账单 | 不计 | 对已有误记由本人确认修正 |
| 未确定性质/疑似重复 | 显示“待确认”且不进入公开排名 | 报告显示遗漏数量和原因 | 不假装全部数据完整 |

例：期间收入 ¥1,000、消费 ¥200、期间退款 ¥50、确认的自有转账 ¥300，现金结余为 ¥850；毛支出 ¥200，退款流入 ¥50。退款若来自上期，不能说本期实际买东西只花了 ¥150，需单列说明。

金额在数据库和聚合中使用 Decimal；接口传定点字符串，不用浮点做并列判断。排名按未四舍五入金额比较，展示两位小数时必须避免看似相同却无解释的名次。

预算现状只有当前规则，无当期历史。新增 BudgetRevision 或周期快照，从启用后留历史；历史缺失明确显示“无可核验的当期预算”。不能拿 9 月调整后的预算推断 8 月是否超支。

### 排行阶段二

先做自愿加入的好友自然月榜；结余不是资产、余额或信用等级，数据由用户记录，不能证明真实财富。不挂奖金、不发金融信用分。结余偏向高收入者，长期可探索个人目标完成度，但不能在没验证时包装为公平比较。

统一 UTC+8。进行中周期用共享口径；结束后生成不可变快照，任务幂等，失败可重试，并先显示“结算中”。封榜必须基于周期关闭时冻结的输入/事务水位；如果定时任务晚到，不可直接拿晚到后的最新账本冒充关闭时状态。正式做日/月/年全榜前补账单版本或周期截止快照机制。

退出/隐藏金额即时影响历史展示，不改快照金额；重新加入不恢复过去已退出周期的参与。好友榜按当前互关关系筛选。并列采用竞赛排名 1、1、3，并以有效记账天数作为同额次级排序。上线不补造过去榜单。

## 5. AI 复盘：受限工具编排，而非开放财务代理

复用现有模型配置与适配器；新增专用只读工具白名单，不把 create/delete 工具带入复盘运行。第一版流程固定、可审计，不宣传无边界的自主 Agent。

1. 用户选已结束自然日/月；服务端从登录身份取 ownerId，不接受模型指定别人的身份。
2. 服务端全量聚合该周期账单并记录数据水位、统计版本、排除条目数量；不使用最多 50 条的聊天查询代替完整数据。
3. 取当前有效且获准送 AI 的主评/回复，未撤回、未违规；匿名化作者标识。没人评价就明确写“暂无好友反馈”。
4. 取可核验的历史预算；缺失时跳过预算超支结论。
5. 输入结构化财务事实和不可信文字区域。评论中的指令不改变系统权限，也不触发工具写入。
6. 输出固定结构：事实摘要、朋友观点、AI 建议、证据引用、数据缺口、最多三条行动。引用指向用户自己的账单或可见评语。
7. 服务端校验数字、引用归属及输出结构，不让模型自行计算结余；失败可重试，复盘作业有幂等键。
8. 保存 reportVersion、inputDigest、model/provider、promptVersion、ruleVersion、generatedAt 与来源引用。模型名称不意味着可重复生成相同文本。

原报告不随账单编辑静默改写；显示“来源已更新，可重新生成”。内容被判违规后，关联报告先失效/隐藏相关引用并要求重新生成，阻断旧报告重新展示违规文字。主人可删除报告。报告仅主人可见，评价者不能借报告拿到其他人的意见。

验收关注准确引用、权限和可执行建议，不采用“AI 省了多少钱”这种未实测承诺。

## 6. Monad 集成建议：可携带、可独立验证的复盘凭证

**待用户确认的可选模块。** 建议对应 Track 04：Trust, Identity & AI Infrastructure。社群本身是中心化授权关系，不冒充开放社交图谱；账单不是链上支付，不为套 Track 02 临时加托管钱包。

用途：用户导出自己主动选择的报告公开版本，离开知账后仍可验证“该钱包在该时点登记了这一版本，该包后来有没有变”。独立校验器可在不登录知账、只连公开 RPC 的情况下工作。实现这个完整用户动作，才比单纯往链上塞 hash 更有价值。

### 边界与流程

- 默认不上链；单次明确确认后发布。公开版不含原通知、账单明细、他人原话、昵称或可识别资料，只保留用户选定的本人摘要和行动说明。私有原始报告与公开版分开保存。
- 导出包先预览。使用版本化规范化 JSON、256 bit 随机 salt，承诺 `keccak256(domain || canonicalPayload || salt)`，domain 含 schemaVersion、chainId、contractAddress，避免低熵金额裸哈希和跨域混淆。salt 保存在用户导出包，不单独公布。
- 用户钱包签名；绑定账号使用一次性 nonce、时效和域校验。平台不保存用户私钥；普通知账用户无需钱包。
- 最小合约 Registry 保存 commitment、schemaVersion、issuer、登记区块信息及撤销状态；允许签名者撤销/替换，防重放。链上不存金额、评价或完整报告。
- 状态：draft → awaiting_signature → submitted → confirmed；失败可重试、拒签回到 draft；仅见交易哈希不能显示 confirmed。核验 chainId、合约地址、receipt 成功与事件内容；处理网络切换、重复提交和撤销。
- 独立 verifier 接收用户主动提供的导出包，规范化并重算承诺，读取登记记录，展示 matched/mismatch/revoked/not_found；修改任何一字必须 mismatch。它只能证明一致性和签名者声明，不能证明银行交易真实、财务建议正确、模型真正执行过或完整账本未被挑选。
- 交易地址、时间、登记频次仍公开且可能关联身份；撤销不能抹掉链上历史。链上状态不可冒充可删除的私有数据。报告被审核失效后不能再从知账导出，已外发文件无法追回。

### 实施最小量

独立 `contracts/` + `verifier/`；NestJS 新增 proofs 模块，提供导出包和可选状态缓存；缓存不是验证权威。移动端先用系统浏览器打开钱包签名/校验页，避免为演示重做 RN 钱包底层；深链需校验随机会话与归属。

只用 Monad 测试网及测试 gas，无储值、收益承诺、代币发行或排行榜金融奖励。延迟/gas 用部署后的真实交易测量，不引用峰值当项目实测。实施前核对 RPC/浏览器与钱包兼容性。

赛道比较：Track 04 与报告来源、用户选择披露最接近；Track 03 需要更强的开放图谱/可携带社群价值，目前私密评账不足以声称已达成；Track 02 需要真实链上支付设计优势，本方案暂无。Track 01 不匹配。仅有 hash 上链仍有“链上必要性弱”的评审风险，独立验证、用户导出和修改检测必须真实可演示。

## 7. 工程落点与接口建议

保留模块化单体，不拆微服务、不动 Bot/AstrBot。

| 新增模块/模型建议 | 职责与约束 |
|---|---|
| social：Follow、Block、ReviewGrant | owner/reviewer 唯一；中央授权服务；grant 状态和版本；邀请接受规则 |
| reviews：ReviewSubject、BillVote、ReviewThread、ReviewMessage、MessageRevision | subject/reviewer 唯一；billId 可空、删除后只读；文本版本隔离 |
| notifications：InboxEvent、ReadCursor、OutboxEvent | 事务内写 outbox；投递幂等、重试、合并；当前授权复查 |
| ledger：entryKind + LedgerSemanticsService | 统一排除、退款、币种和期间口径 |
| retrospectives：ReviewJob、ReviewReport、ReportEvidence | owner/period/inputDigest 幂等；只读 AI；引用失效管理 |
| rankings（阶段二）：Participation、PeriodSnapshot | 显式加入、封榜版本、水位和金额权限 |
| moderation：ContentReport、ModerationAction | 最小举报上下文、审计、被隐藏内容阻断 |
| proofs（可选）：WalletBinding、ProofRecord | 签名者绑定、链状态索引；不保存私钥 |

拟新增 API（不是现有接口）：`/social/grants`、`/social/reviewers`、`/social/owners/:id/bills`、`/reviews/subjects/:id/vote`、`/reviews/threads`、`/retrospectives`、`/retrospectives/:id/export`、`/proofs`。使用用户 JWT；审核走 `/admin-api/moderation` 独立管理权限。与现有 `/bills/:id` 私有接口分开，不扩大它的读权限。

授权校验至少覆盖 owner/reviewer、拉黑、grant 当前状态、收支、业务日期、创建时点、账单删除状态；校验及写入用同事务或锁策略避免“检查后撤权仍写入”。缓存按 grantVersion 失效，React Query 在退出账号/撤权时移除敏感缓存。API 返回专用投影，不返回整个 Prisma Bill。

迁移先加表/可空字段、回填标记、功能开关；不得未经确认把旧用户设成社群已开启/已参榜。删除/统计变更需回归现有客户端兼容。正式发布前备份并在临时库演练，生产源代码和本地基线核对后再发布。

| P1 私密评账 | 主动授权、两名评价者、投票/回复/撤回、拉黑、基础举报、应用内未读 | 4–6 人日 | 端到端闭环和跨用户越权测试通过 |
| P2 复盘 | 结束周期、全量聚合、证据、历史/删除、模型失败处理 | 2–3 人日 | 数字由服务计算、引用不越权 |
| P3 可选凭证 | 合约、签名页、导出与独立验证 | 3–4 人日 | 真实测试网交易＋篡改失败＋撤销 |
| 提交验收（10/13 前） | 稳定性、真机、APK、视频、代码增量说明 | 1–2 人日 | 可访问演示及提交材料完整 |

三天内做完整原方案不现实。杭州版优先演示现有自动记账/AI能力，新增流程明确标“设计提案”；如会前有已测试的新能力再替换相应页面。全球提交版至少完成 P0–P3（选择链上方向时）；排行榜、陌生人申请、全平台推送与完整公开关系网后置。

每次移动端改动遵循仓库版本递增、短路径 Release 构建和 app-version 同步规则。本轮仅写材料，不虚增 APK 版本。

## 9. 验收与度量

关键验收：A 授权 B/C 后二者各自仅看四字段和本人线程；猜 ID/直接 API/深链/缓存都不能看到他人内容；撤权与并发写入时权限一致；编辑、撤回、删除和举报不会绕过；AI 不因评论指令扩大权限；转账与跨期退款不污染结余；月底/UTC+8 边界测试；模型无反馈时不编造；导出不含原文或他人信息；测试网报告篡改被独立校验器识别。

试点指标：授权接受率、收到首条真实评语的比例、复盘生成成功率、引用正确率、下一周期复盘返回率、建议被采纳的自报比例、误识别修正率。记录样本量与观察期；这些是待测指标，没有既有提升数值。

商业假设：先验证免费小圈子复盘的留存，再研究可选高级历史分析或用户自带模型；不靠出售私密账单、评论或链上画像盈利。用户愿不愿邀请一个朋友、是否愿第二次看报告，比先做全站排行榜更值得检验。
