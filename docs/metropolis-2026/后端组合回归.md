# 后端组合回归

入口位于 `backend/test/run-social-regression.cjs`。在后端目录运行：

```powershell
npm test -- --runInBand
npm run test:social:integration
```

需要已安装后端依赖、可用 Docker 和包含 `bf7edae78addaae80bea246f24ba4328b4b7f408` 的 Git 历史。执行器重新生成 Prisma Client、编译 Nest，然后启动随机名称 `zhizhang-regression-<UUID>` 的 PostgreSQL 16 临时容器，仅绑定本机 `15447`、`15448`、`15449`、`15451`；端口占用时失败，不停止现有服务。运行器自行设置合成数据库连接，不接受生产数据库作为目标。

每个数据库用 `bf7edae`（通知样本/社群升级前）的 schema 建立旧版基线，再顺序执行当前 001–016 迁移，包含预算留档和复盘隐私失效触发器，而不以 `db push` 代替迁移。每组升级测试前用 Prisma diff 检查结果与当前 schema 一致；预算历史专项先升级到 010，带已有预算执行 011，再应用后续迁移并检查最终 schema。未来新增 schema 或迁移时须维护这条升级路径，结构差异会导致失败。覆盖本次升级的全部 001–016；该 Git 基线不是当前生产结构的证明，正式发布前仍须比对生产库实际 schema 与迁移记录。

覆盖十四组真实数据库/HTTP 链路：预算历史迁移、统一账务、账本累计结余、预算进度、关系授权、评账申请、私密文字、文字写入限流、举报审核、消息中心、新账单通知队列、排行榜、AI 证据取数、持久化复盘。最后运行四种模型适配器的本机 HTTP 模拟测试。此前未组合执行的预算基线与 AI 取数专项现已纳入；本命令仍不代替全部生产验收。

测试包含刻意触发的通知写入异常和上游模型失败，日志中会出现相应 ERROR；是否通过以断言及进程退出码为准。没有连接外部模型，也不消耗模型额度。用到的用户名、账单和密钥均为合成数据。

正常完成或捕获到失败后，执行器停止自己创建的容器，由 Docker 自动删除容器及其匿名数据卷，并清理本次系统临时目录。不会清理项目运行数据或其他容器。强制结束进程或 Docker 不可用可能中断清理，需检查带 `zhizhang.synthetic-regression=true` 标签的本次容器并按完整名称停止。

这组检查不能替代真机跨账号、实际供应商模型质量、系统推送、生产迁移/发布、支付闭环和路演演示验收。当前生产版本见[0.0.152 发布记录](生产发布-0.0.152.md)。

## 升级前备份与旧库恢复演练

组合运行器先调用 `test/recovery-rehearsal.cjs`，在同一个随机临时容器内新建两个专用数据库。以 bf7edae schema 建立旧库，写入合成用户、四位小数消费/关联退款、中文备注和预算，使用容器内 pg_dump 获取升级前备份，再执行 001–016 迁移并比较原业务行完整内容。随后故意修改升级库金额，把备份恢复到另一个空库，校验旧 schema、全部样本字段、退款关系、自增序列和外键约束。

恢复目标从不使用原库或生产地址；备份只含本轮合成数据，保存在进程内且不输出 dump 内容。所有测试数据库随临时容器清理。这是备份恢复路径的可重复验证，不是线上回滚命令：生产操作仍须核对实际基线、停写窗口、备份落盘与可恢复性、应用版本配套以及备份后的新增写入处置。该演练没有证明比 bf7edae 更早的升级、生产数据量下的耗时、跨版本 PostgreSQL 恢复或真实数据恢复时间目标。

2026-09-17：新增恢复演练与后续十二组数据库链路、四适配器 36 次请求均通过，退出码 0，临时容器已清理。


## 完整升级路径与 016 修复

改用通知样本和社群升级之前的 Git 基线后，首次执行发现 15 个迁移没有创建 `system_settings` 与 `admin_issues`，且 001 的通知样本用户外键缺少 `ON UPDATE CASCADE`。旧的 cd1acb8 基线已经包含这些表和正确 schema，因而无法暴露该缺口。

016 增量迁移在事务内创建缺失管理表与索引，已存在的表和数据保持不变；随后重建通知样本外键使其与 Prisma 一致。不能修改已发布的 001 来代替此修复。恢复演练增加已存在管理数据的保留断言，以及用户 ID 更新时通知样本跟随更新的实际约束测试。应用不会因此新增修改用户 ID 的产品入口。

单独复查备份恢复可运行 `npm run test:social:integration -- --recovery-only`；输出会明确未运行业务测试，不能把它当作完整组合回归通过。默认无参数仍执行全部链路。

最终验证：完整 001–016 路径的 12 组测试与 36 次适配器请求通过；最终恢复脚本的管理数据保留、外键级联和旧库恢复单独复核通过，退出码均为 0。
