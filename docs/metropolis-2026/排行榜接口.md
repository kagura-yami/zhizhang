# 排行榜后端与封榜规则

R08 后端与 0.0.143 移动端排行榜、参榜/金额设置、逐笔账务确认已接通。完整社群入口、原生设备回归和生产部署仍待完成，不能把接口或浏览器通过视为完整功能上线。

## 统计与隐私

- 日、月、年均按 UTC+8 自然周期划分；支持全站和当前互关好友范围。
- 复用 `LedgerAccumulator`：普通收入 + 退款流入 − 普通支出，Decimal 四位小数；转账、调账、误记不计入。结余不是资产、银行余额或真实财富认证。
- 有有效收支且本周期没有待确认账单才参榜。零及负结余参与；完全无有效收支不参与。存在未分类、分类过期、币种不符等情况时，本人收到 `needs_review` 与待确认条数，不用不完整金额参榜。需要后续手机端补齐账务确认入口。
- 结余降序、有效记账天数降序；两项相同并列，采用 `1,1,3` 名次。用户 ID 仅稳定分页位置，不打破并列。
- 默认不参与、隐藏金额。当前 `rankingScope` 为 `global` 才能出现在全站榜；好友榜接受 `global/friends`，按当前互关关系筛选（包含本人）。
- 他人金额隐藏时返回 `amount: null`，不会先发送金额再由前端遮挡；本人始终可看自己的金额。拉黑、停用、退出、当前参榜范围和金额设置也适用于历史榜。
- 仅返回用户 ID、昵称、头像及名次/天数等榜单字段；点击资料不产生评账授权，不返回账单明细。

## API

所有接口要求用户 JWT、账户激活并已启用社群，返回 `{success:true,data:...}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rankings/periods?kind=day\|month\|year&page=1&pageSize=20` | 从当前周期倒序列出开放周期；每页至多 50 条，附 `closed` |
| GET | `/rankings?kind=month&period=2026-09&scope=global\|friends&page=1&pageSize=20` | 榜单分页、总人数、`mine`、`myPage`、本人未参榜原因 |
| PATCH | `/social/preferences` | 复用已有 `rankingScope: none/friends/global`、`showRankingAmount` 设置 |

周期格式：日 `YYYY-MM-DD`、月 `YYYY-MM`、年 `YYYY`。拒绝不存在的日期、未来周期和首次部署前已结束的周期。

榜单项含 `user`、`rank`、稳定分页 `position`、`effectiveDays`、`amount`、`amountHidden`。`mine` 独立于当前页，`myPage` 可直接定位；未上榜时均为 null。`mineStatus`：`ranked`、`not_participating`、`friends_only`、`no_period_record`、`needs_review`、`no_valid_entries`。待确认条数仅返回本人的 `myPendingCount`。

## 封榜与事务

新增 `ranking_launch`（首次部署时间）、`ranking_states`（本次参与及日/月/年游标）、`ranking_results`（期间金额、天数、有效/待确认数、口径版本）。

1. 显式加入时仅初始化当时未结束的周期；其内旧账单可以计入。首次迁移前已选择参榜的用户从部署当日/月/年起初始化，不追溯其启用社群时间。
2. 所有应用账单写入、财务分类确认、启动时自动账单分类补全先锁定该用户，再在同一事务中 `prepareRanking`：用修改前账本封存自上次游标以来已结束的周期。
3. 完成账单变更后，在同一事务、同一捕获时刻调用 `refreshRanking` 更新当前日/月/年结果。账单写入或投影失败一起回滚；边界以获得用户锁后的事务时刻为准。
4. 老于游标的封榜数据不重算。后台每分钟预计算跨期用户；读榜时也补齐过期投影才返回，停机恢复不依赖定时任务准点运行。正常读榜从聚合表排序分页，不每次扫描全站原始账单。
5. 退出删除该次参与的聚合记录。重新加入创建当前周期的新参与记录，不恢复任何旧封榜数据；其他用户的封榜金额保留，名次按剩余参与者实时计算。
6. 账单读取每页 500 条，覆盖全部数据，无先截断再统计。数据库索引支持用户日期扫描和周期排名。

应用写路径必须继续遵守上述锁和前后钩子。直接 SQL 改账或同时运行未包含钩子的旧版 API 会破坏历史语义，不能当作正常运维方式。
